# Дорожная карта

Документ описывает крупные этапы разработки. Дорожная карта задаёт ориентиры и может уточняться по мере появления тестовых данных и кода. Детальные задачи ведутся в [backlog.md](backlog.md).

## Этап 1. Каркас проекта

Цель этапа — подготовить минимальную структуру C++-проекта, в которой можно развивать вычислительные модули и проверять их независимо.

Основные результаты:

- настроен CMake-проект для консольного приложения;
- подготовлены общие CMake Presets;
- добавлена базовая структура каталогов исходного кода;
- подключены выбранные сторонние библиотеки;
- подготовлен vcpkg-манифест для зависимостей, которые удобно устанавливать через vcpkg;
- добавлен небольшой пример вызова оптимизатора из PETSc;
- добавлен небольшой пример решения СЛАУ через UMFPACK;
- подключён CTest;
- подготовлена инфраструктура для GoogleTest;
- подготовлена инфраструктура для Google Benchmark;
- добавлены настройки форматирования и статического анализа;
- определён минимальный исполняемый файл приложения.

## Этап 2. MVP решателя прямой задачи

Цель этапа — получить первый сквозной решатель прямой задачи на ограниченном наборе возможностей.

На этом этапе в каждом основном модуле реализуется один надёжный вариант алгоритма. Интерфейсы модулей должны позволять позже заменить реализацию или добавить альтернативный метод без переписывания всего расчёта.

Основные результаты:

- представлены входные данные прямой задачи во внутреннем формате программы;
- реализованы процедуры вычисления теплофизических коэффициентов;
- реализована модель зрелости EASY%Ro;
- реализован простой временной цикл;
- реализована одна неявная временная схема;
- реализован один способ решения нелинейной задачи;
- реализован один способ решения линейных систем;
- реализована простая пространственная дискретизация для тестовой сетки;
- реализовано вычисление расчётных величин в точках наблюдений;
- сформирован результат прямого расчёта: статус, невязки, значение целевой функции и базовая статистика;
- добавлены тесты для ключевых автономных компонентов.

## Этап 3. Первый решатель обратной задачи

Цель этапа — подключить к прямому решателю минимальный механизм подбора калибруемых параметров.

Основные результаты:

- задан интерфейс между оптимизатором и решателем прямой задачи;
- реализовано формирование вектора параметров и ограничений;
- реализован расчёт нормированных невязок для температур и отражательной способности витринита;
- подключён один простой алгоритм поиска параметров;
- добавлен сквозной тест на искусственной задаче;
- зафиксированы кандидаты на дальнейшее сравнение алгоритмов обратной задачи.

## Этап 4. Адаптация прямого решателя под тестовые данные

Цель этапа — после получения тестовых данных уточнить устройство сеток, геометрии и входных файлов, а затем доработать прямой решатель под реальные данные.

Основные результаты:

- реализован разбор формата входных данных;
- реализована загрузка геометрической истории, литотипов, пористости, граничных функций, начального условия, кинетики EASY%Ro и измерений;
- уточнено представление сеток и соответствие данных между эпохами;
- доработана пространственная дискретизация под фактическое устройство сеток;
- реализован или уточнён перенос состояния между эпохами.

## Этап 5. Baseline на тестовых данных

Цель этапа — получить первый воспроизводимый вариант прямого решателя на тестовых данных, с которым можно сравнивать дальнейшие изменения.

Основные результаты:

- проверена корректность прямого расчёта на доступных тестовых данных;
- выбран базовый сценарий запуска;
- зафиксирован способ сравнения последующих изменений с baseline.

## Этап 6. Профилирование и оптимизация

Цель этапа — определить реальные дорогие места расчёта и улучшать производительность измеряемым образом.

Основные результаты:

- добавлены измерения времени работы основных модулей программы;
- подготовлены скрипты или команды для воспроизводимого запуска бенчмарков;
- подготовлен способ сравнения результатов с baseline;
- выбраны приоритетные направления оптимизации;
- ключевые оптимизации проверяются измерениями.

## Этап 7. Расширение набора алгоритмов

Цель этапа — сравнить альтернативные методы внутри отдельных модулей и выбрать полезные улучшения.

Кандидаты для сравнения:

- временные схемы;
- контроллеры шага по времени;
- методы решения нелинейной задачи;
- линейные решатели;
- предобуславливатели;
- варианты пространственной дискретизации;
- способы переноса состояния между эпохами;
- алгоритмы обратной задачи.

Основные результаты:

- альтернативные методы подключаются через существующие интерфейсы;
- сравнение выполняется на одинаковых входных данных и настройках;
- для принятых методов фиксируются результаты сравнения;
- неиспользуемые экспериментальные варианты удаляются или остаются явно помеченными как экспериментальные.

## Этап 8. Пользовательский интерфейс и эксплуатация

Цель этапа — довести консольное приложение до удобного запуска и анализа результатов.

Основные результаты:

- описан стабильный интерфейс командной строки;
- добавлены понятные сообщения об ошибках для основных отказов;
- реализован вывод результатов в согласованном формате;
- добавлены режимы запуска прямой и обратной задачи;
- добавлена пользовательская документация;
- подготовлены примеры запуска.
