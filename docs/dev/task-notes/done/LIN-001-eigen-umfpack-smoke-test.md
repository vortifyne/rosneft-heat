# LIN-001: Проверка Eigen и UMFPACK

## Цель

Проверить, что проект может собрать и запустить минимальный пример решения разреженной СЛАУ через UMFPACK.

Предпочтительный путь для smoke-теста:

```text
vcpkg -> eigen3 + suitesparse -> Eigen::UmfPackLU -> решение маленькой разреженной СЛАУ
```

Такой вариант проверяет сразу две вещи: доступность SuiteSparse/UMFPACK в сборке и удобный C++-интерфейс Eigen для дальнейших экспериментов с линейной алгеброй.

## Источники

- [vcpkg package: `eigen3`](https://vcpkg.io/en/package/eigen3.html)
- [vcpkg package: `suitesparse`](https://vcpkg.io/en/package/suitesparse.html)
- [Eigen: UmfPackSupport module](https://eigen.tuxfamily.org/dox/group__UmfPackSupport__Module.html)
- [SuiteSparse](https://people.engr.tamu.edu/davis/suitesparse.html)

## Подключение через vcpkg

В `vcpkg.json` предполагается добавить зависимости на Eigen и SuiteSparse:

```json
{
  "dependencies": [
    "eigen3",
    "suitesparse"
  ]
}
```

При реализации нужно проверить, какой вариант vcpkg фактически предоставляет доступ к UMFPACK:

- пакет `suitesparse`;
- feature `suitesparse[gpl]`;
- отдельный порт `suitesparse-umfpack`, если он доступен в используемой версии vcpkg.

Эта проверка нужна из-за лицензионного ограничения. Если доступ к UMFPACK через vcpkg требует включения GPL-компонентов, такую зависимость нельзя использовать в проекте. В этом случае нужно зафиксировать результат проверки и выбрать другой способ подключения линейного решателя.

Результат проверки должен быть отражён в CMake-конфигурации проекта или в документации по сборке.

## Подключение в CMake

Для Eigen ожидается подключение через CMake config:

```cmake
find_package(Eigen3 CONFIG REQUIRED)
```

Для SuiteSparse/UMFPACK нужно использовать CMake targets или config-файлы, которые предоставляет vcpkg в выбранной версии. Имена target'ов не фиксируются в этой заметке заранее, потому что их лучше подтвердить на рабочей сборке.

## Минимальная задача

Для smoke-теста используется маленькая разреженная система с точно известным решением:

```text
A = [  4  -1   0
      -1   4  -1
       0  -1   3 ]

b = [15, 10, 10]^T
```

Точное решение:

```text
x = [5, 5, 5]^T
```

Матрица малая, но её нужно хранить и решать как разреженную.

## Ожидаемый workflow Eigen

Пример должен демонстрировать минимальную последовательность:

- создать `Eigen::SparseMatrix<double>`;
- заполнить матрицу через triplets;
- создать правую часть `Eigen::VectorXd`;
- создать `Eigen::UmfPackLU<Eigen::SparseMatrix<double>>`;
- выполнить `compute` или пару `analyzePattern` и `factorize`;
- вызвать `solve`;
- проверить `solver.info()`;
- сравнить найденное решение с `(5, 5, 5)`.

Для доступа к обёртке Eigen над UMFPACK используется:

```cpp
#include <Eigen/UmfPackSupport>
```

## Ожидаемый результат

Желательный результат задачи:

- пример собирается в составе CMake-проекта;
- пример запускается локально;
- в примере явно используется `Eigen::UmfPackLU`;
- найденное решение близко к `(5, 5, 5)`;
- есть простой способ повторить запуск: через CTest или отдельную документированную команду.

## Не входит в задачу

- общий интерфейс линейного решателя проекта;
- подключение матриц из дискретизации задачи теплопереноса;
- сравнение UMFPACK с итерационными методами;
- предобуславливатели;
- крупные тесты производительности;
- оптимизация параметров SuiteSparse.
