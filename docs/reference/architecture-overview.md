# Обзор архитектуры

Документ описывает верхнеуровневое разделение программы на вычислительные компоненты. Подробные математические модели и численные методы описываются в отдельных справочных материалах.

## Общая схема

Программа строится как набор слабо связанных модулей. Верхние уровни управляют ходом расчёта, нижние уровни выполняют специализированные вычислительные операции.

```text
Решатель обратной задачи
    └── Решатель прямой задачи
          ├── Интегрирование по времени
          ├── Решение нелинейных систем
          │     └── Решение линейных систем
          │           └── Предобуславливатель
          ├── Пространственная дискретизация
          ├── Работа с геометрией и сеткой
          ├── Вычисление теплофизических коэффициентов
          ├── Модель зрелости EASY%Ro
          ├── Диагностика, статистика и профилирование
          └── Ввод и вывод данных
```

Основная архитектурная цель — отделить физическую постановку, численные методы, хранение состояния и инфраструктурные части программы. Это должно позволить развивать модули независимо и сравнивать разные алгоритмы внутри одного компонента.

## Решатель обратной задачи

Решатель обратной задачи подбирает калибруемые параметры модели по измерениям температуры и отражательной способности витринита.

Компонент отвечает за:

- представление вектора параметров;
- учёт допустимых диапазонов параметров;
- выбор очередного набора параметров;
- запуск прямого решателя;
- обработку вектора невязок и значения целевой функции;
- остановку оптимизации по выбранным критериям.

Решатель обратной задачи не должен зависеть от деталей сетки, временной схемы, способа сборки матрицы или метода решения СЛАУ.

## Решатель прямой задачи

Решатель прямой задачи управляет расчётом температурного поля и связанных величин на всей геологической истории при фиксированном наборе параметров.

Компонент отвечает за:

- подготовку начального рабочего состояния;
- проход по эпохам и временным шагам;
- вызов временного интегратора;
- обновление состояния после принятого шага;
- перенос состояния между эпохами;
- вычисление расчётных значений в точках наблюдений;
- формирование результата прямого расчёта.

Результат прямого расчёта должен включать статус завершения, невязки, значение целевой функции и диагностическую информацию, достаточную для анализа отказов и производительности.

## Интегрирование по времени

Интегратор по времени управляет шагами по времени и вызывает решатель нелинейной задачи для очередного временного слоя.

Компонент отвечает за:

- выбор размера шага;
- ограничение шага границами эпох;
- подготовку данных предыдущих временных слоёв;
- принятие или отклонение шага;
- передачу принятого состояния наружу.

Интегратор не должен зависеть от деталей вычисления потоков через грани или от конкретного линейного решателя.

## Решение нелинейных систем

Нелинейный решатель работает с системой вида `F(x) = 0`, возникающей на неявном временном шаге.

Компонент отвечает за:

- вычисление текущей невязки;
- построение или запрос линейной системы для очередной поправки;
- управление нелинейными итерациями;
- проверку сходимости;
- возврат статуса успеха или отказа.

Нелинейный решатель должен использовать абстракцию задачи, а не знать детали уравнения теплопереноса.

## Решение линейных систем

Линейный решатель получает систему вида `Ax = b` и возвращает решение или статус отказа.

Компонент отвечает за:

- выбор метода решения;
- применение предобуславливателя, если он используется;
- контроль сходимости итерационного метода;
- сбор статистики по итерациям и отказам.

Линейный решатель не должен зависеть от того, какая физическая задача породила матрицу.

## Предобуславливатель

Предобуславливатель используется только с итерационными линейными решателями. Он ускоряет решение линейных систем и настраивается отдельно от пространственной дискретизации.

Компонент отвечает за:

- построение внутреннего представления по матрице;
- применение предобуславливателя к вектору;
- решение о повторном использовании или перестроении, если это поддерживается.

## Пространственная дискретизация

Пространственная дискретизация переводит уравнение теплопереноса, граничные условия и условия на внутренних контактах в алгебраическую систему.

Компонент отвечает за:

- вычисление балансов по ячейкам;
- вычисление потоков через грани;
- учёт граничных условий;
- учёт контактов между подобластями;
- сборку невязки и линейной системы;
- работу с коэффициентами, предоставленными физическим модулем.

Этот компонент является одним из основных мест, зависящих от фактического устройства сеток.

## Геометрия и сетка

Модуль геометрии и сетки хранит пространственное описание расчётной области и предоставляет операции, необходимые другим компонентам.

Компонент отвечает за:

- представление узлов, ячеек, граней и связности;
- хранение меток подобластей и литотипов;
- восстановление геометрии внутри эпохи;
- предоставление геометрических величин для дискретизации;
- сопоставление данных между конфигурациями соседних эпох.

После получения тестовых данных устройство этого модуля должно быть уточнено под фактический формат сеток.

## Вычисление теплофизических коэффициентов

Физический модуль вычисляет коэффициенты уравнения теплопереноса по литотипам, пористости, температуре и параметрам модели.

Компонент отвечает за:

- температурные зависимости свойств скелета;
- свойства флюида;
- эффективную теплопроводность;
- эффективную объёмную теплоёмкость;
- объёмное радиогенное тепловыделение;
- проверку допустимости физических значений, если такая проверка требуется.

Модуль не должен знать, каким численным методом затем используются рассчитанные коэффициенты.

## Модель зрелости EASY%Ro

Модуль EASY%Ro обновляет интегральную характеристику термической истории материальных частиц и вычисляет отражательную способность витринита.

Компонент отвечает за:

- хранение накопленных аррениусовских интегралов;
- обновление интегралов после принятого временного шага;
- вычисление степени превращения;
- вычисление расчётной отражательной способности витринита;
- предоставление значений в точках наблюдений.

Обновление зрелости должно выполняться только для принятого временного шага.

## Диагностика, статистика и профилирование

Диагностический слой собирает информацию о ходе расчёта и помогает анализировать корректность, устойчивость и производительность.

Компонент отвечает за:

- статусы завершения расчётов;
- причины отказов;
- число принятых и отклонённых шагов;
- число итераций нелинейных и линейных решателей;
- базовую статистику времени работы модулей;
- данные для сравнения вариантов расчёта.

Диагностика не должна существенно усложнять вычислительные модули и должна отключаться или упрощаться в производительных режимах.

## Ввод и вывод данных

Модуль ввода и вывода связывает внутренние структуры программы с внешними файлами.

Компонент отвечает за:

- чтение входных данных;
- запись результатов расчёта;
- запись диагностической информации;
- преобразование внешних форматов во внутренние структуры.

Вычислительные модули не должны напрямую зависеть от формата файлов.

## Направление зависимостей

Зависимости должны идти от управляющих компонентов к специализированным интерфейсам, а не к деталям реализации.

Допустимые примеры:

- решатель обратной задачи вызывает решатель прямой задачи через интерфейс вычисления невязок;
- временной интегратор вызывает нелинейный решатель для построенного временного шага;
- нелинейный решатель вызывает линейный решатель через интерфейс решения `Ax = b`;
- пространственная дискретизация запрашивает геометрию и теплофизические коэффициенты через специализированные интерфейсы.

Нежелательные примеры:

- оптимизатор напрямую обращается к ячейкам сетки;
- линейный решатель знает о литотипах или граничных условиях;
- модуль ввода-вывода управляет временным циклом;
- физический модуль зависит от конкретной схемы дискретизации.

## Горячие циклы

Высокоуровневые интерфейсы полезны для операций уровня «сделать шаг», «собрать систему», «решить СЛАУ» или «вычислить невязки».

Внутренние циклы по ячейкам, граням, реакциям и степеням свободы должны оставаться простыми для оптимизации. В них не следует без необходимости использовать динамический полиморфизм, сложные виртуальные вызовы или лишние аллокации.
