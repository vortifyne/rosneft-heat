# Архитектура программы

Программа содержит модельную задачу на регулярной сетке и полную задачу теплопереноса в
осадочном бассейне. Обе задачи используют общие средства линейной алгебры, решения нелинейных
систем и интегрирования по времени, но имеют разные сетки и пространственные дискретизации.

## Общая последовательность вычислений

```text
решатель прямой задачи
    -> интегратор по времени
        -> временная схема
            -> полудискретная задача
        -> нелинейный решатель
            -> линейный решатель
                -> разреженная матрица и векторы
```

Зависимости направлены сверху вниз. Линейный решатель не знает о температуре и сетке,
нелинейный решатель — о временной схеме, а интегратор — о способе вычисления потоков.

## Общие численные средства

Каталог `src/linear/` содержит:

- `Vector` — владеющую оболочку над `Eigen::VectorXd`;
- `SparseMatrix` — разреженную матрицу в формате CSR или CSC;
- `LinearSolver` — общий интерфейс решения системы `Ax=b`;
- `UmfpackLinearSolver` — используемый прямой решатель.

Каталог `src/nonlinear/` содержит описание нелинейной системы и `NonlinearSolver`. Решатель
управляет итерациями Пикара или Ньютона, проверяет сходимость, при необходимости сокращает
поправку и вызывает выбранный линейный решатель. Полная задача сейчас использует метод Пикара.

Каталог `src/time/` содержит историю решения, временные схемы и `TimeIntegrator`. Схема BDF1
строит нелинейную задачу очередного шага. Интегратор принимает новое состояние только после
сходимости и точно заканчивает шаг в заданный момент времени.

Пространственная задача реализует интерфейс `SemiDiscreteSystem`. Поэтому временная схема не
зависит ни от вида сетки, ни от конкретного уравнения.

## Модельная задача

Каталог `src/model/` содержит простую задачу на прямоугольной регулярной сетке:

- `ModelHeatSystem` собирает полудискретное уравнение;
- `ModelHeatForwardSolver` выполняет прямой расчёт;
- неизменные данные задачи отделены от калибруемых граничных параметров.

Модельная задача используется для проверки общих численных средств и модельной обратной задачи
из `src/inverse/`. Она собирается в библиотеку `model_heat`.

## Полная бассейновая задача

Каталог `src/basin/` содержит управление полным расчётом:

- `BasinInput` читает внутренние таблицы и предоставляет геологические конфигурации;
- `BasinForwardSolver` хранит неизменные данные задачи и выполняет расчёты с заданными
  граничными параметрами;
- `BasinState` объединяет сетку, температуру, свойства ячеек и состояние EASY%Ro;
- `BasinMeshMotion` перемещает сетку и обновляет пористость внутри эпохи;
- `BasinForwardOutput` сохраняет поля и краткие таблицы расчёта;
- `layered_mesh` строит сетку, согласованную со слоями.

`BasinForwardSolver` создаётся один раз для выбранных входных данных, размера ячейки и шага по
времени. Метод `solve` получает только профили поверхностной температуры и базального теплового
потока. Такое разделение позволяет повторно использовать подготовленную задачу при калибровке
параметров.

Полный ход расчёта описан в [отдельной заметке](basin-forward-model.md).

## Сетка и пространственная дискретизация

`Mesh2D` из `src/mesh/` владеет сеткой TQMesh и предоставляет представления ячеек и граней без
копирования их геометрии. Рабочая сетка строится из явно заданных четырёхугольных и треугольных
ячеек. Отдельные способы построения произвольной треугольной или смешанной сетки не входят в
рабочий путь.

`HeatSystem` из `src/discretization/` реализует ячеечный метод конечных объёмов. Он собирает
невязку и матрицу отдельными функциями для накопления, внутренних потоков, источника и граничных
условий. Градиент восстанавливается независимым модулем `LeastSquaresGradient`.

Перенос полей между различными сетками находится в `src/mesh/mesh_transfer.*`. Особенности
геологических слоёв и назначение начального состояния новому материалу остаются в `src/basin/`.

## Физические модели

Каталог `src/physics/` не зависит от сетки и численных решателей:

- `thermophysical_properties` вычисляет эффективные теплопроводность, объёмную теплоёмкость и
  радиогенное тепловыделение;
- `EasyRoModel` накапливает кинетические интегралы и вычисляет отражательную способность
  витринита.

Свойства пересчитываются по текущей температуре при сборке задачи. EASY%Ro обновляется только
после принятого временного шага.

## Ввод и вывод

Исходные таблицы XLSX разбираются средствами Python перед запуском вычислительного ядра:

```text
XLSX -> tools/basin_data.py -> tools/prepare_forward_data.py -> CSV -> BasinInput
```

Python используется только для подготовки данных. Температура и EASY%Ro вычисляются в C++.
Результаты записываются в VTU, PVD и небольшие таблицы CSV.

## Цели сборки

| Цель | Назначение |
| --- | --- |
| `heat_numerics` | линейная алгебра, нелинейный решатель и интегрирование по времени |
| `model_heat` | модельная прямая задача |
| `basin_heat` | сетка, физика и полная бассейновая задача |
| `heat_forward` | запускаемый файл полной прямой задачи |
| `model_unit_tests` | проверки общих средств и модельной задачи |
| `heat_unit_tests` | проверки полной задачи и её самостоятельных модулей |

Модельная обратная задача и POUNDERS включаются параметром CMake
`HEAT_BUILD_MODEL_INVERSE=ON`.

## Границы модулей

- Особенности бассейна не передаются в линейную алгебру, нелинейный решатель и интегратор.
- Формулы свойств не зависят от сетки и метода конечных объёмов.
- Ввод и вывод не управляют временным циклом.
- Рабочее состояние расчёта не хранится внутри общих численных средств.
- Циклы по ячейкам, граням и реакциям не создают лишних копий и временных объектов.
- Новые варианты алгоритмов добавляются только при наличии задачи, для которой текущего рабочего
  пути недостаточно.
