# Запуск и просмотр результатов

Для работы нужны программы `basin_forward_solver`, `basin_inverse_solver` с их библиотеками и инструменты
из каталога `tools/`. Подготовка данных и просмотр используют Python; зависимости устанавливает
`uv` по файлам `pyproject.toml` и `uv.lock`. Команды выполняются из папки программы.

## Расчёт

Поместите подготовленные таблицы в `input/`: `configurations.csv`, `layers.csv`,
`boundaries.csv`, `lithotypes.csv`, `kinetics.csv`. Запустите:

```bash
./basin_forward_solver input result
```

Программу, собранную в Docker, запускайте через скрипт: он использует библиотеки контейнера.

```bash
tools/run_basin_forward.sh input result
```

В `result/snapshots/` появятся снимки `snapshot_*.cgrd`, а в `result/` — итоговый файл
`summary.txt` с параметрами и числом шагов и итераций. Для нового расчёта выбирайте
новый каталог результатов.

Снимки сохраняются после каждого шага: `snapshot_e01_s0001.cgrd` — эпоха 1,
шаг 1. Шаг 0 — начальное состояние эпохи, при смене сетки — после переноса;
последний снимок — состояние после конечного переноса. Во время расчёта выводятся
текущие эпоха, шаг, геологический возраст и процент пройденного времени моделирования.

В конце программа выводит время работы по частям и доли от общего времени; эта же таблица
сохраняется в `timings.txt`. Статистика по эпохам и шагам записывается в `epochs.csv`
и `timesteps.csv`.

EASY%Ro использует табличную первообразную при линейном изменении температуры за шаг.
Таблица строится автоматически один раз при первом вычислении.
Диапазон таблицы: `20 ≤ E/(Rg·T) < 200`. Для исходных энергий реакций это температуры
примерно от 181,3 до 856,1 K. При другой кинетике температурные пределы меняются.

Начальное поле температуры — средняя по X температура поверхности в начальный момент
плюс градиент 30 °C/км. Оно не зависит от заданного базального потока.
Для сохранения только конечного поля добавьте `--snapshots final`.

## Обратная задача

Подготовка XLSX той же командой создаёт `observations.csv`, если присутствуют файлы
`TemperatureWellData.xlsx` и `VitriniteWellData.xlsx`. Заданный поток в обратных входах не требуется.

```bash
./basin_inverse_solver input inverse_result --maxiter 100 --maxfev 500
```

В Docker используйте `tools/run_basin_inverse.sh input inverse_result`.
Подбирается пространственно постоянный поток 50–100 мВт/м², не возрастающий к современности;
значения задаются на границах эпох и линейно интерполируются по времени.
Начальное приближение задаёт `--initial-q` в мВт/м², по умолчанию 75.
Стартовая точка POUNDERS подрезается с учётом `-tao_pounders_delta`.

Невязки нормируются на погрешности измерений; для температуры 2% вычисляются в °C.
Расчёт останавливается при согласовании всех измерений, сходимости оптимизатора или достижении
лимита. `--residual-tol 0` отключает остановку по погрешностям. Параметры PETSc передаются
после собственных аргументов программы, например `-tao_pounders_delta 0.01`.

Результат — `parameters.csv`; `observations.csv` содержит сравнение с замерами,
`summary.txt` — причину остановки и невязки, `progress.csv` — ход подбора.
`--save-forward` добавляет один прямой расчёт с сохранением снимков в `forward/`.
Найденный поток можно использовать отдельно:

```bash
./basin_forward_solver input result --parameters inverse_result/parameters.csv
```

## Просмотр

```bash
uv run --frozen python tools/view_basin_snapshots.py result
```

Ползунок выбирает сохранённое состояние. Для отображения зрелости витринита добавьте
`--field reflectance`, для слоёв — `--field layer`.

## Подготовка исходных таблиц

Если данные даны в XLSX, положите их в `data/` и перед расчётом выполните:

```bash
uv run --frozen python tools/prepare_basin_input.py data input
```

Для сборки в Docker подготовку данных из XLSX и расчёт можно выполнить одной командой:

```bash
tools/run_basin_from_xlsx.sh data result
```
