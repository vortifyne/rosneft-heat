# Запуск и просмотр результатов

Команды выполняются из корня проекта. Нужны Docker, `uv` и собранные решатели
(см. [сборку](../dev/development-process.md)). Скрипт сам преобразует XLSX;
для каждого запуска выбирайте новый каталог результатов.

## Прямая задача

### 1. Запуск

```bash
tools/run_basin_from_xlsx.sh path/to/input result
```

Первый путь — каталог XLSX, второй — каталог результатов.

| Опция | Назначение | По умолчанию |
| --- | --- | --- |
| `--dx`, `--dz` | Размеры ячеек по горизонтали и вертикали, м | 200, 50 |
| `--dt-ma` | Шаг времени, млн лет | 1 |
| `--rdp-tol` | Допуск упрощения геометрии, м; 0 отключает | 5 |
| `--axis-rdp-tol` | Дополнительное упрощение только оси столбцов, м | Отключено |
| `--min-height` | Минимальная высота ячейки, м | 0.05 |
| `--scheme` | Схема: `linear` (MPFA), `nmpfa` | `linear` |
| `--linear-method` | Решатель: `gmres`, `bicgstab`, `lu` (UMFPACK), `fgmres` | `gmres` |
| `--pc` | Для собственного FGMRES доступны `none`, `ilu`, `ilu2`. Для решателей PETSc также доступны `gamg` и `boomeramg` | `ilu2` |
| `--pc-reuse` | Повторное использование предобуславливателя: `none`, `step`, `epoch` | `none` |
| `--linear-rtol`, `--linear-atol` | Относительный и абсолютный допуски линейного решателя | `1e-8`, `1e-50` |
| `--linear-maxiter` | Лимит линейных итераций | 1000 |
| `--nonlinear-rtol`, `--nonlinear-atol` | Относительный и абсолютный допуски Пикара | `1e-8`, `1e-8` |
| `--nonlinear-maxiter` | Лимит итераций Пикара | 200 |
| `--snapshots` | Снимки полей: `all` или только `final` | `all` |
| `--parameters` | CSV с историей потока, например `inverse_result/parameters.csv` | Поток из XLSX |

В режиме `--linear-method fgmres` длина рестарта равна 30. При выборе ILU
факторизация строится для каждой линейной системы. Уровень заполнения можно
переопределить, например `--linear-method fgmres --pc ilu -pc_factor_levels 2`.

Дополнительные опции PETSc ставятся в конце, например `-ksp_gmres_restart 200`
(по умолчанию рестарт через 100 векторов).
Скрипт выдаёт `Temperature.xlsx` (°C) и `Sweeney_Burnham_1990_EASY_Ro.xlsx` (%Ro)
на исходной геометрии для всех возрастов. Снимки полей — в `snapshots/`,
настройки и статистика — в `summary.txt` и `timings.txt`.
В новых снимках `CGRID003` на контакте слоёв сохраняются отдельные значения
%Ro с каждой стороны. Просмотрщик также открывает снимки `CGRID001` и `CGRID002`.

### 2. Визуализация

```bash
uv run --frozen python tools/view_basin_snapshots.py result
```

| Опция | Назначение | По умолчанию |
| --- | --- | --- |
| `--field` | Поле: `temperature` (K), `reflectance` (Ro, %), `layer` | `temperature` |
| `--observations` | CSV со скважинами и точками измерений в конечной конфигурации | Без наложения |
| `--save` | Путь к рисунку, например `field.png` | Окно с ползунком снимков |

Для сравнения двух каталогов результатов или двух отдельных XLSX:

```bash
uv run --frozen python tools/compare_basin_results.py reference result --save comparison
```

Первый путь — эталон. Скрипт проверяет совпадение геометрии и выдаёт максимальную
абсолютную ошибку, RMSE и относительную L2 для `Top`, `Bot`, `Aver` по всем возрастам
(по табличным значениям, без весов).
`--age` выбирает возраст рисунков (по умолчанию 0 млн лет); `--save` сохраняет PNG
и `summary.csv`, без него открываются окна. Ошибка на рисунках — расчёт минус эталон.

## Обратная задача

### 1. Запуск

```bash
tools/run_basin_from_xlsx.sh --inverse local/inverse_problem_data/data inverse_result --snapshots final
```

`--inverse` ставится перед путями. Подбирается история потока снизу;
в консоли видны итерация, целевая функция и число измерений T и Ro в пределах погрешности.

Доступны общие опции прямого расчёта из таблицы выше, кроме `--parameters`, и следующие:

| Опция | Назначение | По умолчанию |
| --- | --- | --- |
| `--method` | Метод основного 2D-подбора: `pounders` или `gauss-newton` | `pounders` |
| `--initial-q` | Начальный поток, мВт/м² | 75 |
| `--initial-parameters` | CSV с начальной историей потока; заменяет `--initial-q` | Не задан |
| `--section-x` | Координата сечения в метрах для подбора начального потока в 1D | Не задана |
| `--section-well` | Имя скважины для 1D. Укажите хотя бы одну, повторяя опцию для каждой скважины | Не задана |
| `--maxiter` | Лимит итераций оптимизатора | 10 |
| `--maxfev` | Лимит вычислений функции; может быть превышен при построении начальной модели | 100 |
| `--residual-tol` | Допуск для всех невязок, нормированных на погрешность; 0 отключает критерий | 1 |

Файл `--initial-parameters` задаёт фиксированные возраста узлов и начальные значения
потока. Число строк данных задаёт число степеней свободы. Например, для задачи
от 200 до 0 млн лет можно использовать три узла:

```csv
age_ma,basal_heat_flux_mw_m2
200,90
137.5,72
0,60
```

Нужно минимум два узла. Первая и последняя строки соответствуют началу и концу
расчёта. Возраста строго убывают, значения потока лежат в диапазоне [50, 100] мВт/м²
и могут уменьшаться или оставаться постоянными. Между узлами поток меняется линейно.
Решатель подбирает длину шага так, чтобы точно дойти до каждого узла потока. В тепловом балансе используется среднее
значение потока за шаг, а для температуры на подошве — поток на конец шага.
Без CSV узлы совпадают с границами эпох и получают значение `--initial-q`.
В `parameters.csv` сохраняются все узлы подбора. Этот файл можно передать прямому
решателю через `--parameters`. В XLSX поток интерполируется на возраста исходной геометрии.

Для старта из одномерного подбора задайте сечение и скважины, например:

```bash
tools/run_basin_inverse.sh prepared-input inverse_result --section-x 500 --section-well A --section-well B
```

В этом режиме узлы потока берутся из `--initial-parameters` или из границ эпох,
а 1D-подбор начинается с постоянного `--initial-q` (75 мВт/м² по умолчанию).
Гаусс–Ньютон подбирает поток по наблюдениям выбранных скважин в пределах сечения.
Лимиты и допуск применяются к каждому подбору отдельно. В 2D передаётся профиль с
наименьшей достигнутой 1D-невязкой. Если точек в сечении нет, используется постоянный
поток. Фактический старт записывается в `initial_parameters.csv`. Для 2D используются все исходные наблюдения.

Опции PETSc также идут в конце.
У POUNDERS итерация 0 строит начальную модель и требует нескольких прямых расчётов.
После подбора скрипт выполняет итоговый прямой расчёт в `forward/` и выдаёт две
XLSX с полями и `Heat_Flow_Basal.xlsx` с найденным потоком на исходной геометрии.
Результат: `parameters.csv` — найденный поток, `observations.csv` — сравнение с измерениями,
`progress.csv` — ход подбора, `summary.txt` — итог.

### 2. Визуализация

```bash
uv run --frozen python tools/view_basin_inverse.py inverse_result
```

Показывает начальный и найденный поток, T и Ro по скважинам, невязки и сходимость.
Единственная опция `--save figures` сохраняет PNG в указанный каталог;
по умолчанию открываются окна.

Поля итогового расчёта:

```bash
uv run --frozen python tools/view_basin_snapshots.py inverse_result/forward --field reflectance --observations inverse_result/observations.csv
```

Опции и значения по умолчанию — как при визуализации прямой задачи.

## Графическое приложение Basin Solver

Единый файл `dist/BasinSolver-x86_64.AppImage` содержит прямой и обратный
решатели, их зависимости и визуализатор от организаторов `basin_viewer.py`.
Устанавливать Python или MPI отдельно не требуется.

```bash
chmod +x dist/BasinSolver-x86_64.AppImage
./dist/BasinSolver-x86_64.AppImage
```

Если FUSE недоступен, добавьте `--appimage-extract-and-run`.
На главном экране доступны `Forward solver`, `Inverse solver` и `Visualize data`.
В решателе выберите входной каталог кнопкой `Pick a folder with data`:
он появится в дереве слева, нажатие раскрывает используемые XLSX.
Параметры таблицы редактируются до запуска `Start`; во время расчёта они
заблокированы. `Stop` останавливает текущий расчёт, журнал остаётся внизу.
Кнопка закрытия рабочего экрана возвращает к главному меню.

Результаты сохраняются рядом с входными каталогами:
`results/<имя входного каталога>/<имя входного каталога>_run-<дата-время-id>/`.
Поле `Result name suffix` позволяет задать своё окончание, например `data1_run-test` для каталога `data1` и значения `test`.
Если родительский каталог недоступен для записи, используется
`Документы/Basin Solver Results/<имя входного каталога>/`.
Прямая задача создаёт `Temperature.xlsx` и
`Sweeney_Burnham_1990_EASY_Ro.xlsx`; обратная дополнительно создаёт
`Heat_Flow_Basal.xlsx` с найденным потоком. Путь выводится в журнал.

Вкладка `visualize` использует просмотрщик организаторов: выбор свойства,
возраста, сечения и профиля. После расчёта она открывает его результаты,
до расчёта — совместимые таблицы выбранного входного каталога.
В обратной задаче `Simple` показывает этот просмотрщик, а `Advanced`
пока содержит только неподвижные оси q и t, ма.
`Visualize data` в главном меню открывает тот же просмотрщик отдельно.
Данные читаются без создания кэша в исходном каталоге.

### Сборка AppImage

На машине с Docker и `squashfs-tools` сначала соберите базовый образ,
затем приложение:

```bash
make docker-image
packaging/linux/build.sh
```

Готовый файл и его SHA256 появляются в `dist/`.
Для повторной сборки после изменения Python-интерфейса, когда образ и
зависимости уже собраны:

```bash
HEAT_SKIP_IMAGE_BUILD=1 HEAT_OFFLINE_DEPS=1 packaging/linux/build.sh
```

Сборка сохраняет изолированный MPI runtime, загрузчик `orted` и ограничение
компонентов hwloc, чтобы не подключать несовместимые библиотеки системы
и не ожидать ответа графического сервера во время инициализации решателя.

После успешного расчёта кнопка `Performance` показывает длительность этапов,
их долю в общем времени и самый долгий этап. На экране параметров кнопка
относится к последнему результату выбранного входного каталога. В просмотрщике
она открывает отчёт выбранного результата, в том числе после перезапуска
программы. Для этого откройте каталог результата в разделе визуализации.
Диаграмма внутри солвера показывает проценты от времени самого солвера.
Исходные измерения хранятся в компактном файле `performance.json`
в корне каталога результата. Для старых расчётов без отчёта кнопка недоступна.
