# Запуск прямого расчёта

Рабочий способ запуска состоит из подготовки исходных таблиц средствами Python и последующего
вызова программы на C++.

## Требования

Для воспроизводимой сборки нужны Docker Engine и GNU Make. Для чтения XLSX на основной системе
должен быть установлен [uv](https://docs.astral.sh/uv/). Зависимости Python описаны в
`pyproject.toml` и устанавливаются `uv` автоматически.

Исходные данные должны находиться в каталогах
`local/forward_problem_data/data1` и `local/forward_problem_data/data2`. Каталог `local/`
исключён из Git.

## Сборка и проверка

Образ достаточно собрать один раз:

```bash
make docker-image
```

Рабочая сборка и автоматические проверки:

```bash
make docker-release
make docker-test
```

Исполняемый файл создаётся по пути `build/release/heat_forward`.

## Расчёт data1

```bash
tools/run_forward.sh \
    local/forward_problem_data/data1 \
    local/results/data1-forward
```

## Расчёт data2

```bash
tools/run_forward.sh \
    local/forward_problem_data/data2 \
    local/results/data2-forward
```

Для каждого запуска следует выбирать новый или предварительно освобождённый каталог результата:
сценарий не удаляет оставшиеся в нём файлы прежнего расчёта.

## Параметры

Полная форма команды:

```text
tools/run_forward.sh DATA OUTPUT [CELL_SIZE] [DT_MA]
```

| Параметр | Назначение | Значение по умолчанию |
| --- | --- | ---: |
| `DATA` | каталог исходных XLSX | обязательный |
| `OUTPUT` | каталог подготовленных данных и результата | обязательный |
| `CELL_SIZE` | целевой размер ячейки, м | 50 |
| `DT_MA` | шаг времени, млн лет | 0,25 |

Например, расчёт с ячейкой 100 м и шагом 0,5 млн лет запускается так:

```bash
tools/run_forward.sh \
    local/forward_problem_data/data1 \
    local/results/data1-h100-dt0.5 \
    100 \
    0.5
```

Всегда используются все конфигурации входного набора и рабочая послойная сетка. Других режимов
построения сетки в команде запуска нет.

## Состав каталога результата

Сценарий сначала создаёт подкаталог `input/` с внутренними таблицами:

- `configurations.csv` — возраста конфигураций;
- `layers.csv` — геометрия, литотипы и пористость;
- `boundaries.csv` — поверхностная температура и базальный тепловой поток;
- `lithotypes.csv` — свойства литотипов;
- `kinetics.csv` — параметры EASY%Ro.

В корне каталога результата создаются:

- `temperature.pvd` — временной ряд для ParaView;
- `state_*.vtu` — сетка и поля в сохраняемые моменты;
- `statistics.csv` — размеры сетки и диапазоны температуры и EASY%Ro;
- `epochs.csv` — число шагов, итераций и время каждой эпохи;
- `transitions.csv` — число ячеек до и после перестроения;
- `energy-balance.csv` — глобальный баланс энергии;
- `summary.csv` — итоговая строка расчёта, включая время и объём файлов.

## Просмотр в ParaView

Откройте `temperature.pvd`. ParaView загрузит последовательность состояний с их расчётным
временем. Основные поля:

- `temperature` — температура в К;
- `Ro` — отражательная способность витринита, %;
- `porosity` — пористость;
- `layer_id` и `lithotype` — номер слоя и код литотипа;
- `velocity_z` — вертикальная скорость в м/с.

Для наблюдения движения сетки используйте обычное представление `Surface` без преобразования
координат.

## Отладочная сборка

Для поиска ошибок можно собрать вариант без оптимизации:

```bash
make docker-debug
```

Полные и сравнительные расчёты следует выполнять сборкой Release.
