# Запуск прямого расчёта

Запуск состоит из подготовки исходных таблиц средствами Python и последующего
вызова программы на C++ в Docker-образе `heat-env`.
Команды выполняются из корня репозитория; входные и выходные каталоги должны находиться
внутри него. `tools/run_heat_forward.sh` запускает уже подготовленные CSV без повторного
чтения XLSX и фиксирует один вычислительный поток.

## Требования

Для воспроизводимой сборки нужны Docker Engine и GNU Make. Для чтения XLSX на основной системе
должен быть установлен [uv](https://docs.astral.sh/uv/). Зависимости Python описаны в
`pyproject.toml` и устанавливаются `uv` автоматически.

Исходные данные должны находиться в каталогах
`local/forward_problem_data/data1` и `local/forward_problem_data/data2`. Каталог `local/`
исключён из Git.

## Сборка и проверка

Образ достаточно собрать один раз:

```bash
make docker-image
```

Рабочая сборка и автоматические проверки:

```bash
make docker-release
make docker-test
```

Исполняемый файл создаётся по пути `build/release/heat_forward`.

## Расчёт data1

```bash
tools/run_forward.sh \
    local/forward_problem_data/data1 \
    local/results/data1-forward
```

## Расчёт data2

```bash
tools/run_forward.sh \
    local/forward_problem_data/data2 \
    local/results/data2-forward
```

Для каждого запуска следует выбирать новый или предварительно освобождённый каталог результата:
сценарий не удаляет оставшиеся в нём файлы прежнего расчёта.

## Параметры

Полная форма команды:

```text
tools/run_forward.sh DATA OUTPUT [CELL_SIZE] [DT_MA] [SOLVER_OPTIONS...]
```

| Параметр | Назначение | Значение по умолчанию |
| --- | --- | ---: |
| `DATA` | каталог исходных XLSX | обязательный |
| `OUTPUT` | каталог подготовленных данных и результата | обязательный |
| `CELL_SIZE` | целевой размер ячейки, м | 50 |
| `DT_MA` | шаг времени, млн лет | 0,25 |

Например, расчёт с ячейкой 100 м и шагом 0,5 млн лет запускается так:

```bash
tools/run_forward.sh \
    local/forward_problem_data/data1 \
    local/results/data1-h100-dt0.5 \
    100 \
    0.5
```

Линейный решатель выбирается дополнительными ключами:

```bash
tools/run_forward.sh \
    local/forward_problem_data/data1 \
    local/results/data1-gmres-ilu \
    --linear-solver petsc-gmres-ilu
```

| Ключ | Значение по умолчанию |
| --- | --- |
| `--linear-solver` | `umfpack`; варианты PETSc приведены ниже |
| `--linear-rtol` | `1e-8` |
| `--linear-atol` | `1e-50` |
| `--linear-max-iterations` | `1000` |

PETSc является обязательной зависимостью сборки и включён в Docker-образ.
Варианты PETSc задаются именами `petsc-gmres-{ilu|ilu2|gamg|boomeramg}` или
`petsc-bicgstab-{ilu|ilu2|gamg|boomeramg}` (например, `petsc-gmres-ilu2`).
Используются последовательные GMRES с рестартом 30 или BiCGStab и левый
предобуславливатель ILU(0), ILU(2), GAMG либо hypre BoomerAMG.
Для BoomerAMG нужна сборка PETSc с hypre; Docker-образ включает эту зависимость.
Параметры построения AMG используются из настроек по умолчанию библиотеки. Критерий сходимости
использует предобусловленную невязку PETSc; невязка исходной линейной системы дополнительно
не вычисляется. Предобуславливатель
по умолчанию строится заново для каждой матрицы. Варианты AMG с суффиксом `-reuse`
(например, `petsc-gmres-boomeramg-reuse`) сохраняют предобуславливатель первой матрицы
эпохи до её окончания; сама температурная матрица обновляется на каждом решении.
На границе эпохи AMG строится заново. При несходимости или ошибке линейного решения расчёт
завершается с ошибкой.
Допуски и предел итераций относятся к итерационным методам.

Например, повторный расчёт по уже подготовленным таблицам:

```bash
tools/run_heat_forward.sh \
    local/results/data1-gmres-ilu/input \
    local/results/data1-gmres-ilu-repeat \
    --linear-solver petsc-gmres-ilu
```

Расчёт охватывает все конфигурации входного набора и использует послойную сетку.

## Состав каталога результата

Сценарий сначала создаёт подкаталог `input/` с внутренними таблицами:

- `configurations.csv` — возраста конфигураций;
- `layers.csv` — геометрия, литотипы и пористость;
- `boundaries.csv` — поверхностная температура и базальный тепловой поток;
- `lithotypes.csv` — свойства литотипов;
- `kinetics.csv` — параметры EASY%Ro.

В корне каталога результата создаются:

- `temperature.pvd` — временной ряд для ParaView;
- `state_*.vtu` — сетка и поля в сохраняемые моменты;
- `statistics.csv` — размеры сетки и диапазоны температуры и EASY%Ro;
- `epochs.csv` — число шагов, итераций и время каждой эпохи;
- `transitions.csv` — число ячеек до и после перестроения;
- `energy-balance.csv` — глобальный баланс энергии;
- `timings.csv` — время основных частей расчёта;
- `summary.csv` — итоговая строка расчёта, включая время и объём файлов.

В `timings.csv` раздельно приведены работа с сеткой, сборка вместе с вычислением свойств,
линейное решение, EASY%Ro, перенос состояния, запись файлов и неразделённый остаток времени. Эти
значения позволяют определить дорогие части расчёта. Для сравнения быстродействия используют
одинаковые входные данные, сетку и шаг времени; разброс измерений оценивают повторными запусками.

В `summary.csv` также записываются наименьшая поперечная толщина и наибольшая вытянутость ячейки
за весь расчёт.

## Просмотр в ParaView

Откройте `temperature.pvd`. ParaView загрузит последовательность состояний с их расчётным
временем. Основные поля:

- `temperature` — температура в К;
- `Ro` — отражательная способность витринита, %;
- `porosity` — пористость;
- `layer_id` и `lithotype` — номер слоя и код литотипа;
- `velocity_z` — вертикальная скорость в м/с.

Для наблюдения движения сетки используйте обычное представление `Surface` без преобразования
координат.

## Отладочная сборка

Для поиска ошибок можно собрать вариант без оптимизации:

```bash
make docker-debug
```

Полные и сравнительные расчёты следует выполнять сборкой Release.
