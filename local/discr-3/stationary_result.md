# Стационарный результат NTPFA на C-сетке

Дата: 2026-10-25. Статус: отрицательный результат для принятого сейчас
сочетания NTPFA + обычный Пикар + UMFPACK. Перенос в полную задачу отложен.

## Что реализовано и проверено

- В книге `local/discr/FVM_INMOST_2020.pdf` неоднородной скалярной
  теплопроводности соответствует §2.3. Из его трёхмерного построения выведена
  двумерная пара направлений: целевая грань и одна вспомогательная. На
  nonmatching стыке один физический сегмент получает один общий поток.
- При фиксированном приближении матрица вертикальных потоков использует только
  две соседние ячейки; верхние вертикальные ступени Дирихле дают вклад только
  в свою ячейку. Веса гасят лишь вспомогательные **ячейочные** остатки;
  известные граничные температуры и потоки остаются в свободном члене.
  Регуляризация машинным `epsilon` оставляет остаток порядка машинной точности.
- Геометрический аудит исходной сетки (`original`) при `hx=200`, `hz=100`:
  6464 ячейки, 24892 стороны внутренних вертикальных сегментов, 113 ступеней
  Дирихле с обеих сторон реконструкции, **0 отказов** положительной пары.
  Аудит проверяет именно горизонтальную вспомогательную грань, выбранную
  вычислением потока; максимальное число обусловленности локальной двумерной
  системы направлений — `1,81e5`.
  На `RDP` при `hz=100/25` — 0 отказов при 2129/7208 ячейках. Гармоническая
  точка нередко выходит за короткий сегмент; это диагностируется, но §2.3
  требует принадлежность плоскости грани, а не обязательно самому сегменту.
- Тесты проверяют аффинный поток, скачок `lambda`, баланс на ступенчатой
  поверхности, двухточечный шаблон и знаки коэффициентов. Все четыре
  относящихся к ним теста прошли.

## Сравнение на одном снимке data1, RDP, hx=200

Общее для строк: `phase=0`, `geotherm`, `retained`, `dirichlet_steps`, Пикар,
UMFPACK, допуск нелинейной невязки `1e-8`. RMS и максимум — разность полей
NTPFA и `linear_mpfa` на **одной** сетке, а не ошибка к точному решению.

| hz, м | ячеек | NTPFA обновлений / nnz | linear_mpfa обновлений / nnz | RMS / max разности, К |
| ---: | ---: | ---: | ---: | ---: |
| 100 | 2129 | 222 / 14485 | 9 / 22405 | 3,93 / 6,29 |
| 50 | 3708 | 188 / 25378 | 8 / 39414 | 1,86 / 3,32 |
| 25 | 7208 | 127 / 49504 | 8 / 77144 | 0,352 / 1,86 |
| 12,5 | 13884 | 81 / 95490 | 7 / 148974 | 0,0256 / 0,423 |

Во всех успешно завершившихся случаях глобальный
баланс был порядка `1e-10` или лучше; внутренняя грань консервативна по
построению. При `hz=100` замена начального приближения `geotherm` на `constant`
дала тот же результат, но 236 вместо 222 обновлений.

На исходной геометрии при `hx=200, hz=100` NTPFA не достиг невязки `1e-8`
за лимит 300 обновлений Пикара: на шаге 299 невязка `5,18e-4`. На той же
сетке `linear_mpfa` сошлась за 11 обновлений. Это конкретный отказ текущего
алгоритма решения, хотя геометрически положительная реконструкция существует.

## Решение и пределы

Сейчас NTPFA **не кандидат для полной production-задачи с выбранным Пикаром**:
на целевой исходной геометрии не выполняется действующий лимит итераций, а
на RDP-сетке число прямых решений СЛАУ в 12–25 раз выше линейной схемы, хотя
матрица реже. На мелкой RDP-сетке поля двух схем близки. Устойчивый порядок
ошибки NTPFA относительно независимого предела этим исследованием **не
установлен**: здесь измерена лишь разность двух схем при фиксированном `hx`.
Отрицательный результат относится к обычному Пикару и этим данным, не
опровергает NTPFA с другим нелинейным решателем.

Файлы повторяемых запусков: `local/discr-3/runs-ntpfa-corrected/` и
`local/discr-3/run-rdp-hz100-fixed/`; базовая строка `hz=100` —
`local/discr-3/run-linear-rdp-hz100/`. Более ранние пробные запуски в
`runs-ntpfa-agent/` сделаны до исправления граничных остатков и не должны
использоваться для вывода.
